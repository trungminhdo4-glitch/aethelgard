# AethelGard Report Schema

## Evidence Report

Generated by:

```powershell
python -m aethelgard.cli triage --input tests/fixtures/public_nis2 --out reports/demo --audit
```

File: `evidence_report.json`

Required top-level fields:

- `run_id`
- `timestamp`
- `input_path`
- `document_count`
- `parsed_count`
- `failed_count`
- `evidence_count`
- `categories`
- `per_document`
- `warnings`
- `errors`
- `tool_version`
- `disclaimer`

Each document contains:

- `file`
- `evidence_count`
- `strong_evidence_count`
- `categories`
- `strong_categories`
- `gap_warnings`
- `warnings`
- `evidence`

Strong evidence means `is_compliant == true` and `confidence_score >= 0.7`.
Evidence citations in reports are bounded snippets, capped at 280 characters.

Markdown report sections:

- Scope
- Important Disclaimer
- Executive Summary
- Documents Processed
- Evidence by Category
- Potential Gaps
- Items Requiring Human Review
- False Positive Watchlist
- Recommended Next Manual Checks
- Technical Run Metadata

## Evaluation Report

Generated by:

```powershell
python -m aethelgard.cli eval --fixtures tests/fixtures/public_nis2 --labels tests/fixtures/public_nis2/golden_labels.json --out reports/eval --audit
```

File: `eval_report.json`

Required fields include:

- `status`
- `triage_run_id`
- `document_count`
- `parsed_count`
- `failed_count`
- `evidence_count`
- `documents_total`
- `documents_passed`
- `documents_failed`
- `category_hits`
- `missing_expected_categories`
- `unexpected_categories`
- `evidence_min_pass_rate`
- `false_positive_cases`
- `false_negative_cases`
- `parser_failures`
- `thresholds`
- `threshold_status`

The status is `PILOT_READY` only when all configured synthetic thresholds pass.

## Audit Ledger

Generated only when `--audit` is passed.

File: `reports/audit/aethelgard_runs.jsonl`

Each JSONL entry contains:

- `run_id`
- `timestamp`
- `command`
- `input_path`
- `output_path`
- `document_count`
- `parsed_count`
- `failed_count`
- `evidence_count`
- `evaluation_status`
- `tool_version`
- `content_hashes`
- `warnings`
- `errors`

The ledger stores metadata only. It must not store document contents, full citations,
customer names, secrets, or raw parser output.

## Pilot Readiness Report

Generated by:

```powershell
python scripts/check_pilot_readiness.py --out reports/readiness
```

Files:

- `pilot_readiness.json`
- `pilot_readiness.md`

Status values:

- `PILOT_READY_PAID_CONTROLLED`
- `NOT_READY`
