# AethelGard Report Schema

## Evidence Report

Generated by:

```powershell
python -m aethelgard.cli triage --input tests/fixtures/public_nis2 --out reports/demo --audit
```

File: `evidence_report.json`

Required top-level fields:

- `run_id`
- `timestamp`
- `input_path`
- `document_count`
- `parsed_count`
- `failed_count`
- `evidence_count`
- `categories`
- `per_document`
- `warnings`
- `errors`
- `tool_version`
- `disclaimer`

Each document contains:

- `file`
- `evidence_count`
- `strong_evidence_count`
- `quality_counts`
- `categories`
- `strong_categories`
- `gap_warnings`
- `warnings`
- `evidence`

Strong evidence means the item is compliant, has `confidence_score >= 0.7`, has enough
concrete quality features, and has no hard negative quality signal.
Evidence citations in reports are bounded snippets, capped at 280 characters.

Each evidence item includes:

- `quality`: `strong`, `medium`, `weak`, or `warning`
- `quality_signals`: flags such as `marketing_only`, `template_only`, `outdated`,
  `missing_owner`, `missing_review_date`, `missing_timeline`, or `vague_supplier_controls`
- `concrete_features`: detected support such as owner, review/frequency, process/control,
  output/evidence, timeline, or supplier-control signals

Markdown report sections:

- Scope
- Important Disclaimer
- Executive Summary
- Documents Processed
- Evidence by Category
- Potential Gaps
- Items Requiring Human Review
- False Positive Watchlist
- Recommended Next Manual Checks
- Technical Run Metadata

## Evaluation Report

Generated by:

```powershell
python -m aethelgard.cli eval --fixtures tests/fixtures/public_nis2 --labels tests/fixtures/public_nis2/golden_labels.json --out reports/eval --audit
```

File: `eval_report.json`

Required fields include:

- `status`
- `triage_run_id`
- `document_count`
- `parsed_count`
- `failed_count`
- `evidence_count`
- `documents_total`
- `documents_passed`
- `documents_failed`
- `category_hits`
- `missing_expected_categories`
- `unexpected_categories`
- `evidence_min_pass_rate`
- `false_positive_cases`
- `false_negative_cases`
- `parser_failures`
- `thresholds`
- `threshold_status`

The status is `PILOT_READY` only when all configured synthetic thresholds pass.

## Calibration Report

Generated by `eval` together with `eval_report.json`.

Files:

- `calibration_report.json`
- `calibration_report.md`

These are synthetic calibration indicators only. They include total documents, expected and
detected categories, strong/medium/weak/warning counts, expected gaps, missed gaps,
likely false positives/negatives, per-category precision/recall proxy indicators, threshold
recommendations, and the human-review-required summary.

## Audit Ledger

Generated only when `--audit` is passed.

File: `reports/audit/aethelgard_runs.jsonl`

Each JSONL entry contains:

- `run_id`
- `timestamp`
- `command`
- `input_path`
- `output_path`
- `document_count`
- `parsed_count`
- `failed_count`
- `evidence_count`
- `evaluation_status`
- `tool_version`
- `content_hashes`
- `warnings`
- `errors`

The ledger stores metadata only. It must not store document contents, full citations,
customer names, secrets, or raw parser output.

## Pilot Readiness Report

Generated by:

```powershell
python scripts/check_pilot_readiness.py --out reports/readiness
```

Files:

- `pilot_readiness.json`
- `pilot_readiness.md`

Status values:

- `PILOT_OPS_READY`
- `PILOT_READY_PAID_CONTROLLED`
- `NOT_READY`
